# Cooling

Enable **Settings > System > Cooling > Enable fan controls** to add the Cooling tab. This is off by default and works independently of the Stats feature. Cooling uses the standard notch panel size, with adaptive fan cards and scrolling for narrow layouts or additional fans. Cooling shows actual fan RPM and the hottest readable temperature, with 30%, 50%, 70%, 100%, and Auto controls for each fan.

Presets use the hardware-reported range: `minimumRPM + (maximumRPM - minimumRPM) * fraction`. For a fan with a 2,317–7,826 RPM range, 50% targets about 5,072 RPM and 100% targets 7,826 RPM. Atoll checks the mode and target after a manual write; actual speed may take longer to settle.

Atoll offers **Set Up Fan Control** automatically when Cooling is first enabled or an opted-in user first launches the updated app. First use also offers setup if it has not been completed. Choose **Set Up Fan Control** in the native prompt and approve Atoll in **System Settings > General > Login Items & Extensions**. This optional, signed background helper is registered with `SMAppService.daemon`; registration and approval survive app and Mac restarts. No password is stored. The helper starts on demand, opens AppleSMC only for fan commands, and never reapplies a previous manual preset after restart. **Remove fan helper** disconnects fan control and unregisters the service. Developer-signed builds are required; ad-hoc builds retain session authorization. Distribution builds containing a launch daemon must also be notarized as required by Apple’s ServiceManagement documentation.

Choosing **Not Now** uses session authorization for this launch. Without the optional helper, the first command starts a bundled helper through macOS administrator authorization. Commands share the approved connection until Atoll exits, sleeps, or loses that connection. Closing the notch and rejected commands preserve the session. This fallback installs no persistent service. Authorization cancellation or connection failure requires an explicit Retry connection action rather than repeated automatic prompts.

Turning the feature off closes the helper and returns fans controlled by Atoll to Auto. A command still waiting for authorization is cancelled before it can write. At 95°C or above, the helper raises only the fans controlled by Atoll to 100% and holds them there until you explicitly choose another preset or Auto. A lower preset selected while still hot is applied at 100%, with the effective button and target shown honestly. Cooling displays why the fans were boosted; cooling down does not automatically lower their speed. Explicit Auto remains available at any temperature. The helper still attempts to restore Auto on disconnect, app exit, a 15-second heartbeat expiry, unreadable/invalid temperatures, or failure to confirm a manual fan-speed write. These fallbacks are reported through heartbeat replies and logged. Firmware-controlled fan-stop behavior is allowed in Auto. Both persistent and session helpers share this policy.

## Recovery

The notch shows a direct **Cooling Settings** link when setup, approval, connection, or sensor access needs attention. **Open macOS Approval** opens the OS consent pane; **Reconnect helper** closes the old connection, restores Auto, and checks a fresh connection without applying a saved preset. Cooling settings offer manual setup or helper repair only when needed. Turning Cooling off clears cached setup failures and read-only sensor connections so re-enabling it can recover.

The app/helper identifiers are derived from their own code signatures, and the launchd plist is generated from the product bundle identifier. Locally signed forks must use a distinct bundle identifier instead of inheriting the original publisher’s background-task approval record. The helper identifier is the app identifier with `.cooling` appended. Preferences and macOS privacy approvals belong to the chosen app identity; migrating preferences between identities is a separate installation step.

## Hardware validation

Session helper tested on `Mac17,9`, Apple M5 Pro: two fans with a 2,317–7,826 RPM range. The user confirmed speed changes and one password for successive preset commands. Native Swift sensor reads confirmed both fans in manual mode at a 7,826 RPM target, then both in automatic mode after Auto was selected.

The persistent helper has passed deterministic safety tests and signature checks. On the local M5 Pro installation, macOS approval succeeded with matching local app/helper identities. Authenticated XPC fan commands accepted 50% for both fans without another password, and disconnect restored Auto. App restart reacquired the exclusive helper connection without reapplying a manual preset. Mac-restart behavior still needs device validation.

Intel and other Apple Silicon models have not been hardware-tested. The helper is built for the same architectures as the app; missing SMC keys or invalid sensor limits produce an unavailable/error state. The former 95°C Auto fallback was reproduced on the M5 Pro: both fans returned from 70% to Auto at a recorded 96.4°C, with healthy heartbeats and no app/helper restart. The replacement maximum-speed response passed a signed-helper check on the same M5 Pro at a naturally occurring 100.7°C: 70% requests returned confirmed 100% targets and the heat notice; both fans reached about 7,800 RPM. Targets stayed at maximum when a sample fell to 94.5°C. Closing the diagnostic restored Auto. Watchdog threshold crossing is covered with deterministic fixtures; the physical check exercised hot incoming commands. Forced app failure and sleep cleanup have not been exercised on the physical Mac.

## Development

AppleSMC access uses the native 80-byte host-endian IOKit structure, per-fan `md`/`Md` keys, and `flt ` or `fpe2` RPM encodings. Some firmware requires `Ftst` before manual mode. Both helpers accept only the four presets, Auto, heartbeat, and quit. The persistent helper uses bounded JSON requests over XPC, with mutual Apple signing-anchor, executable-identifier and signing-team requirements, an active-console-user check, and one controller at a time. Its watchdog uses a monotonic clock. The session fallback uses a bounded JSON-line Unix socket. Private directory/socket permissions, peer UID checks, and a random session token authenticate the connection.

Run `sh tests/test_cooling.sh` for SMC value/limit tests and socket/session and deterministic daemon regression tests. Fixtures cover invalid commands, lazy hardware creation, lease renewal/expiry, latched maximum-speed thermal boost, visible sensor fallback, failed-write cleanup, and idempotent disconnect without touching hardware. The session fixture has no SMC writes and needs neither fan hardware nor administrator access. Real hardware read-only inspection is available through `Atoll.app/Contents/Helpers/AtollFanHelper --read-only`.

The AppleSMC reference is [raminsharifi/MacFanControl](https://github.com/raminsharifi/MacFanControl) (MIT). Its complete license notice is in `THIRD_PARTY_FAN_CONTROL.md` and is bundled in the app resources.
